data-ui-size

Same component markup, same engine. data-ui-size re-points the four scale foundations (--cfg-type-min/max + their ratios), so it changes the shape of the scale — base size and step contrast — not just a uniform zoom. Because spacing is all em/lh, the whole layout's density moves with it. Resize the window to see the fluid response; the regions differ purely by config.

Three regions, identical markup

Each column sets data-ui-size on its wrapper. Note the title-to-body contrast grows from sm → lg (the ratio, not just the size), and the card padding/gaps breathe wider — that's lh/em spacing reflowing.

Works anywhere — even nested

An lg region containing a pinned sm card. The inner region just re-declares the foundations; the nearest setter wins, so a dense widget can live inside a spacious page (or vice-versa) with no special handling.

size ≠ scale

Left: data-ui-size="lg" — bigger base and a punchier ratio, so the title pulls further from the body. Right: default md with --scale: 1.18 — a uniform zoom to roughly the same body size, but the title-to-body contrast is unchanged. Same overall size, different typographic character. That's why size re-points the foundations instead of multiplying --scale.
