Color Type Components
Foundation · the color engine

Color is computed, not chosen

You never write a hex value. You declare three numbers — a surface, an ink, a hue — and the engine resolves them into OKLCH lightness and chroma, picks legible contrast, and flips for the active theme. Same declaration, correct color in light or dark.

The three you set
--bgSurface, −1…+1. Sign picks the palette (negative = neutral, positive = the hue); magnitude is loudness.
--fgInk, −1…+1. Magnitude is intensity; negative is neutral, positive is chromatic. The engine flips light/dark for legibility.
--hue0–360. The angle on the wheel. It only colors a surface once --bg goes positive.
The surface matrix · hue × --bg

Every cell is a bare .bg surface — only --hue (row) and --bg (column) change. Notice the left half: below zero, hue is irrelevant, so all rows collapse to the same neutral ladder. From zero rightward, the hue takes over and loudness climbs. No swatch is a literal color.

Ink · --fg and the legibility flip

The same ink declaration lands as dark ink on a light surface and light ink on a dark one — the engine reads the surface lightness and chooses. The two panels below carry identical --fg values; only the surface differs. Flip the theme toggle to watch every value re-resolve.
