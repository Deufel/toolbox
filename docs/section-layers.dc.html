architecture

One ordered spine. Later layers win.

Every rule in system.css lives inside a named @layer, declared once in priority order. Cascade layers beat specificity: a rule in a later layer wins over an earlier one regardless of selector weight. That's why the whole system can ship at specificity 0 (:where() everywhere) and still be predictable — and why your project layer always has the final say.

The declaration

This single statement at the top of the file fixes the order. Everything below just fills these layers in.

@layer reset, styleAPI.color, styleAPI.type, theme, base,
       classAPI.page, classAPI.layout, classAPI.components,
       classAPI.pseudo, classAPI.utility, classAPI.media, project;

Reading the spine

Twelve layers in three movements: the engine (tokens → color + type), the substrate (theme values, bare elements), and the class API (opt-in components + utilities). Your project layer sits last.

Why :where() everywhere

Because layer order already decides conflicts, selectors don't need specificity to win. Wrapping every selector in :where() pins it to 0,0,0. The payoff: any plain class or inline style you write beats the system without a fight — no !important, no specificity wars.

The project layer wins

It's declared last, so it out-ranks every classAPI rule at equal specificity. Your overrides live in one findable place.

@layer project {
  /* final say over classAPI.components */
  .pri { --bg: 1; --fg: -1; }
  .pg-header { --bg: -0.8; }
}
Two tiers, one rule of thumb. The styleAPI.* layers are the engine — token math you tune through theme. The classAPI.* layers are opt-in components. Author against classes; reach into the engine only to retune. This code block, like the ones above, is coloured live by your highlight.js through the classAPI.pseudo layer.
