View transitions

A plain CSS transition animates one property on one element that stays put. The View Transitions API generalizes that to a whole DOM change — elements that appear, move, or leave — by snapshotting before & after and animating between them. system.css wraps it in four direction helpers, gated by your motion switch.

The whole API is one call

Wrap any state change. The browser freezes the old frame, runs your callback, then crossfades to the new frame. No library, no manual FLIP math.

document.documentElement.dataset.vt = "slide-left";
document.startViewTransition(() => {
  // any DOM mutation — swap a route, re-render a list…
  render(nextState);
});

Unsupported browsers just run the callback with no animation — so it's safe to ship today.

Directions ship as helpers

Set data-vt on <html> before you start; system.css keys the keyframes off it.

data-vtmotion
fadeCrossfade (the default if unset)
slide-leftNew content enters from the right
slide-rightNew content enters from the left
scaleSubtle zoom crossfade
It obeys the motion switch — for free. Duration is calc(var(--cfg-motion) * 0.28s), so data-ui-motion off → instant swap, debug → 10× slow, and prefers-reduced-motion zeroes it. Because the transition pseudo-elements live on :root, set data-ui-motion on <html> (not just an inner wrapper) so the value reaches them.

Morph a shared element

Give an element a unique view-transition-name and it becomes its own group — the browser tweens its old and new size/position, so a list card grows into a detail view. This page's demo panel is named vt-demo; the docs shell names its header/nav/footer so they stay put while the content slides.

.card-hero { view-transition-name: hero; }
/* must be UNIQUE per snapshot */

Across separate pages, zero JS

For multi-page sites, one at-rule opts every same-origin navigation into a transition — no script at all. Style it with the same pseudo-elements.

@view-transition { navigation: auto; }

Left off by default in system.css so multi-page sites opt in deliberately.

What the stylesheet defines

The helper block at the end of system.css — pseudo-elements on the document root, keyframes keyed to data-vt:

::view-transition-group(*) {
  animation-duration: calc(var(--cfg-motion) * 0.28s);
}
::view-transition-old(root) { animation-name: vt-fade-out; }  /* default */
::view-transition-new(root) { animation-name: vt-fade-in; }
:root[data-vt="slide-left"]::view-transition-old(root) { animation-name: vt-out-left; }
:root[data-vt="slide-left"]::view-transition-new(root) { animation-name: vt-in-right; }
/* …slide-right, scale… */

Support: Chromium (same- & cross-document), Safari (recent), Firefox (partial) — and a graceful instant swap everywhere else. Only one transition runs at a time.
